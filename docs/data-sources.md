## 二、采集方式

| 项目 | 取值 | 说明 |
|---|---|---|
| 列表深度 | 每源 3 页 | `--pages`，可用 `CSRC_PAGES` / `CSRC_PUNISH_PAGES` / `AMAC_PAGES` 单独覆盖 |
| 单轮请求数 | 约 108 次列表请求 + 详情页 | 只对台账中不存在的条目抓详情 |
| 请求间隔 | **3 秒** | `common.REQUEST_INTERVAL`，串行，不并发 |
| 单轮耗时 | 375–398 秒（实测） | 其中采集约 350 秒 |
| 增量判重 | UID（正文 URL 派生）+ `seen` 表 | 已入库的不再重复抓详情 |
| 缓存 | `data/cache/`，24 小时 | 可随时清空，会自动重建 |

每轮采集的原始结果会落一份快照 `data/raw/penalties_<YYYYMMDD_HHMM>.json`。**快照是判断「这一轮是否真的联网采集过」的唯一可靠证据**；`ledger.json` 的 `last_run` 会被离线重建刷新，不可作为依据。

## 三、容错与降级

- 任一环节失败不阻断后续：采集失败仍用现有台账重建网页与简报，保证用户始终有可用产物；
- 每轮状态写入 `data/last_run.json`（`mode` / 各步返回码 / 新增条数 / 覆盖区间 / 最新快照）；
- 失败时建议追加 `data/run_failures.log`（本仓库不自动写，由宿主侧的定时任务负责）。

## 四、扫描件处理

中基协纪律处分文书绝大多数是**扫描 PDF、无文本层**，走三级抽取：

```
fetch.py 检测无文本层
  → 渲染最多 10 页 PNG（170 dpi）到 data/ocr_queue/<uid>/page_N.png，标 body_status=pending_ocr
  → 视觉逐页转录，写入同目录 transcript.txt（原文照搬、保留文书结构、模糊字「□」占位）
  → python scripts/ocr_apply.py 写回台账（幂等，无需重新抓取）
```

转录规范：原文一字不改、保留标题/文号/当事人段/一二三节/落款/抄送、忽略红头与公章页码、跨页拼接。

## 五、合规约定

1. **只采集公开信息**：全部来自监管机关与自律组织的官网公开栏目，不涉及任何非公开数据、不绕过登录或验证码。
2. **不压站**：串行请求 + 3 秒间隔；请勿把间隔改成 1 秒以下。若目标站出现限流或封禁迹象，应拉长间隔或暂停。
3. **不二次分发原文**：本仓库不携带采集到的处罚原文与转录稿（`data/`、`output/` 已在 `.gitignore` 排除）。需要数据请自行运行采集，或从官方渠道获取。
4. **个人信息**：处罚文书含自然人姓名，仅可用于机构内部合规自查，不得用于画像、歧视性评价或营销（详见 [DISCLAIMER.md](../DISCLAIMER.md) 第六条）。
5. **页面改版即失效**：采集依赖各站栏目结构，监管网站改版会导致对应源返回 0 条。这类失败不会报错，只表现为「当天新增 0」——判断方法是对高产出源单独请求首页，看 TOP 条目是否已在台账中。

## 六、已知的源侧特性

| 现象 | 说明 |
|---|---|
| 辽宁行政处罚、北京监管措施两源常期 0 条 | 属正常：私募相关案件本身少，或该栏目以其他主体为主 |
| 中基协文书落款日期早于发布日 | 常见滞后 1–5 个月；台账 `date` 取网站发布日期，原文落款另存 |
| 同一天多轮运行会写多份快照 | 以文件名时间戳最新的一份为准；差集即为新增 |
